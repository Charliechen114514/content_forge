# 项目文档人工回归案例

这些案例供独立走查验证项目文档判据，不随角色包烘焙。命令与文件名均为假设项目的示例，使用时核对目标项目，不能把它们当作平台的实际用法。

## 安装条件和完成检查缺失

- 原稿：只写“运行初始化命令，然后编译即可”。
- 期望：交代运行目录、实际命令、需编辑的配置和成功后能观察到的结果，必要的宿主接入入口留在对应步骤。
- 归属：review/project-docs 第二、四节。

## 按惯例编造用法

- 原稿：项目只有 Python 工具，README 却写“运行 npm install，然后 npm start”，还给出代码中不存在的默认值。
- 期望：命令与默认值对照当前项目；未确认的用法说明尚未确认，尚未实现的功能标成计划，相对链接从文档所在目录核对。
- 归属：review/project-docs 第三节。

## 按模板凑章节

- 原稿：安装指南补了愿景、设计哲学和路线图，却把命令必需的依赖放在最后。
- 期望：围绕完成安装组织，必要依赖放在命令前，删掉没有对应安装问题的章节。
- 归属：review/project-docs 第一、四节。

## 把操作写成被动结果

- 原稿：“初始化命令应被运行，组合配置应被修改，编译命令应被执行。”
- 期望：写成“在仓库根目录运行初始化命令，然后编辑组合配置，再运行编译命令”。执行者未知时可以保留“文件被意外删除”，不能编出删除者。
- 归属：review/project-docs 第五节。

## 每段交叉引用打断操作

- 原稿：每段都放同一配置说明链接，必要条件只写“详见配置说明”，相同地址在正文手写多次。
- 期望：必要说明就地写够，同一路径只留一次必要入口，延伸阅读与出处集中在文末，Markdown 的地址定义也集中维护。
- 归属：review/project-docs 第四、六节。

## 集中引用后丢了入口或出处对应

- 原稿：删掉下载步骤旁的下载入口，也删掉具体判断旁的来源标记，只留下文末资料列表。
- 期望：必要下载入口保留在步骤旁，判断的来源标记能对上文末出处；独立阅读的章节可以分别保留同一必要入口。
- 归属：review/project-docs 第六节。
