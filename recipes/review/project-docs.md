# 审稿:项目文档(project-docs)

| 层卡 | |
|------|------|
| 维度 | 审稿判据 |
| 档位 | 项目文档 |
| 互斥 | review 维度一次一份，与 writing-style 二选一 |
| 相邻 | 文档任务语境归场景卡，怎么起稿和抽取问题归角色卡，词形规则归 humanizer-zh/rules |
| 让位 | 用户最新裁决与目标项目规则优先，宪法和复审流程照对应层卡执行 |

管辖声明:管项目文档的内容组织、操作完整性、项目事实核对、被动句选择、引用安排和工件排版。不管个人声音语料或复审流程。各走查员只使用其中与自己职责对应的判据，不代替其他走查员。

## 一、按读者任务组织内容

每节都回答读者在当前任务中的一个具体问题，没有对应问题的章节删掉，不为了套模板补章节。默认读者第一次接触项目，作者知道的背景不能默认读者也知道。README 给出适用范围与起步入口，安装指南围绕完成安装组织，配置说明交代如何选值以及效果。

总起句不写成口诀链：不把一组规则压成四到八字一顿的排比，主语省略、动词缩成单字、顿与顿之间零连接，也不拿「一句话」当预告。判断法：拎任何一顿单独念，听不出「谁、对什么、怎么做」就是压过头。真并列的规则列清单，每条一个完整句，总起句只报数目加指向。

## 二、操作能执行，结果能检查

命令前交代运行目录、必要依赖和要替换的值。连续步骤共用的条件在开头写一次，条件改变时再说明。默认给一条完整可用的操作路径，读者只拿到本文和明确提供的前置资料，就能知道该在哪里、用什么值执行。

每段连续操作给一个完成检查，说明成功时能观察到的输出、文件或状态，不要求每条命令后都重复写结果。项目有检查命令时给出命令和成功条件；错误处理只补会阻止该路径完成的已知问题。

## 三、项目事实有依据

本次涉及的命令、路径、配置项和默认值，对照当前版本的代码、配置或已有规范。链接按文档所在目录核对目标。没运行的命令不写成运行过，尚未实现的功能标成计划，找不到依据的用法注明尚未确认，不凭其他项目的惯例补齐。

改写保留事实、代码、命令、路径、链接目标和证据，允许重排句子与移动引用的位置。否定、范围、条件与可能性在改写前后保持一致，不为了让说明更顺而发明原因或状态。

## 四、必要解释就地给够

会改变执行结果的前置条件放在命令前，选配置值需要知道的影响放在配置项旁。当前操作不可缺的解释在本文给够，其余原理可以作为延伸阅读。默认不要求读者先读完整个文档库，不能用链接代替必要说明。判断法：读者会不会先照做，读到后面才发现漏了条件。

## 五、被动句慎用

默认用主动句，执行者明确时写谁做了什么。告诉读者该做什么时，直接写动作，例如“在仓库根目录运行命令”。执行者未知或完全不重要时可以用被动句，不为了改成主动句编出执行者。同一段连续出现被动句时逐句检查，能无损改成主动句的就改；符合条件的被动句不按数量硬删。

## 六、引用集中管理

默认把延伸阅读和出处集中放在文末的参考资料中，没有就不设该节。当前步骤必须访问的入口就地给链接，支撑具体判断的资料在判断旁保留来源标记，让读者能对上文末出处。

判断法：如果读者不跳到另一份文档也能理解当前步骤并继续做，而且这处引用不负责标明判断的出处，就把链接移到参考资料中。同一条操作路径内，同一目标默认只链接一次；不同章节确实需要独立阅读时，可以各留一次必要入口。

Markdown 文档有多个链接时，默认使用引用式链接，把地址定义统一放在文末，同一地址只定义一次；宿主已有引用格式时从宿主。地址定义能复用，不代表同一入口要反复出现在正文中。引用移动后保留原链接目标与出处对应，锚文字交代目标内容，不能只写编号或“这里”。

## 七、排版服务阅读

默认不添加装饰性 emoji，不拿它当列表符号、小节头或句尾装饰；删除后确实丢失信息的符号可以保留。目标项目自己的模板与用户明确指定的格式优先。

断行只服务列表、代码、引用或对话轮换；一句一行的诗歌体并回完整段落。交付说明只补读者从眼前文件或 diff 看不出的原因、影响和下一步，不按文档篇幅另凑一份复述。
